# 供給と送信の収支を毎日見る(読み取りのみ)

送れる企業の在庫が減っていないか(新しく積む数が、送る数に追いついているか)を、毎日1回確かめる手順。
**GET だけ**を使う。DB には書かない。送信・企業探しの API は呼ばない。鍵も要らない。

## いつ見るか

- 平日の 9:30 ごろ(朝の企業探し 6:05・8:05 が終わったあと)。
- **17:30〜19:00 は見ない**(毎日の処理の前後。結果がまだ出ていない)。前の日の 18:00 の分は、翌朝に見る。

## 1. 表を出す

```
node scripts/daily-balance.js              # 今日(日本時間)と直近7日
node scripts/daily-balance.js 2026-10-27   # その日と、その日までの7日
```

出力の例(2026-10-28 16:02 の実際の値):

```
■ ozukanzukan
  日付        曜 回数 見つけ 調べ 保留へ | 送った(フォーム/メール) 不確か 失敗 | 収支
  2026-10-26 月    1     19    3      1 |     13(7/6)            4    0 |  -12
  2026-10-27 火    1      0    3      1 |      0(0/0)            0    0 |   +1
  2026-10-28 水    0      0    0      0 |     10(7/3)            6    2 |  -10
  在庫(今): 送れる 25(★候補 19) / 要確認 65 / 送れない 452 / 保留 6 / 送信待ち 0
  直近の平日1日あたりの送った数: 3.5 → 送れる在庫は 7.1 日分
```

| 列 | 意味 | 元のデータ |
|---|---|---|
| 回数 | 自動パイプラインが動いた回数(18:00 の毎日の処理と、朝の企業探し) | `GET /api/crm?action=auto-pipeline-logs&project=…` |
| 見つけ | 新しく見つけた候補の数(持ち越しから処理した分は含まない) | 同上 `found_count` |
| 調べ | リサーチした数 | 同上 `researched_count` |
| 保留へ | 保留(on_hold)に積んだ数 | 同上 `sent_count`(名前は sent だが、送信の数ではない) |
| 送った | 送信記録の sent と uncertain の合計(uncertain も送った扱い。二度送らない) | `GET /api/send-logs?project=…` |
| 不確か・失敗 | uncertain・failed の数 | 同上 |
| 収支 | 保留へ − 送った | |
| 在庫(今) | 「あとで送る」の今の件数。過去の日の在庫は出せない | `GET /api/crm?action=later-list&project=…` の `counts` |
| 在庫の日数 | 送れる ÷ 直近の平日(今日を除く)1日あたりの送った数 | |

日付は、どれも**日本時間**で数える(記録の作られた時刻・送った時刻から計算)。

## 2. 見るところと目安

| 見るところ | 目安 | 当たったら |
|---|---|---|
| 送れる在庫の日数 | 10日分を切る | 朝の企業探し(`docs/ops/discover.workflow.yml.example`)の回数・`discover_daily_limit` を見直す |
| 収支 | 平日に5日続けてマイナス | 同上。検索の組み合わせ(rotation)が尽きていないか、「見つけ」が0の日が続いていないかを見る |
| 見つけ | 平日に3日続けて0、かつ「調べ」も0 | 持ち越し・検索の組み合わせが尽きている。rotation に市町村・業種を足す |
| 記録 | 「実行時間の都合により処理を打ち切りました」 | 18:00 の処理では毎回出る(48秒で3社ほど)。朝の企業探しで出るなら、1回に調べる数を下げる |
| 記録 | 上の他の文言(エラー) | 文言のとおり確かめる。続くなら Vercel の実行時エラーを見る |
| 失敗 | 送った数の2割を超える | 送信記録の失敗の理由を見る |
| 保留 | 増え続ける | 人が見て送信待ちに入れる(または `auto_release_hold`)。保留は送られない |
| 要確認 | 急に増える | 「あとで送る」の警告の理由を見る(locle を全国にしたあとは `area_review`) |

## 3. 記録に残す(任意)

毎日の結果を残すときは、出力をそのまま日付のファイルに保存する(リポジトリには入れない)。

```
node scripts/daily-balance.js > "収支_$(date +%Y%m%d).txt"
```

## 注意

- 送信記録は、画面から手で送ったもの(trigger が manual・auto)も、送信待ちから送ったものも、すべて含む。
- 「保留へ」は、自動パイプラインが積んだ数だけ。画面から手で保留に入れたもの・「あとで送る」から直接送ったものは含まない。
  そのため収支は「自動の供給 − 全部の送信」の目安で、在庫(今)と合わせて見る。
- 自動パイプラインの記録は直近30日しか読めない(API の作り)。
