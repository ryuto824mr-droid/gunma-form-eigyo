# locle を全国に広げるときのチェックリスト

locle の営業の対象の地域を「群馬県だけ」から「全国」に切り替える手順。上から順に進め、各段階の確認が済んでから次に進む。
ozukanzukan は設定を変えない(群馬県だけのまま)。

## 0. 前提(済み)

- [x] 地域(area)のコードが本番に出ている(2026-10-27 `9c07cbf`。READY・ビルドエラーなし)
- [x] locle と ozukanzukan の二重送信の防止が出ている(`fdc9cc4`)
- [ ] locle の文面(フォーム用・メール用)が決まっている(`docs/ops/locle文面の下書き.md` の【ここに記入】を埋めたもの)

## 1. db-setup(見つけた県の列を足す)

全国のときの「見つけた県と住所の県が違う」判定は、企業の `found_prefecture` 列を使う。列が無くても画面と処理は動くが、
見つけた県が保存されないため、この判定が働かない。

- [ ] 17:30〜19:00 を避ける
- [ ] db-setup を実行する(`POST /api/crm?action=db-setup`。`SETUP_SECRET` が必要。何度実行しても同じ結果になる作り)
- [ ] 確認(読み取りのみ): `GET /api/companies?project=locle&limit=1` の行に `found_prefecture` の項目がある(値は null でよい)
- [ ] 確認: 「あとで送る」(locle・ozukanzukan)の件数が db-setup の前と同じ

## 2. 設定(送信管理の画面 → 自動パイプライン → locle)

今は locle の自動パイプラインの設定の行が無い(切・文面なし)。

- [ ] 文面: 新しく作った locle のフォーム用の文面を選ぶ(今の「初回挨拶フォームⅠ」は短く、全国の文面ではない)
- [ ] 営業の対象の地域: 「全国」
- [ ] 1日の上限(1回に調べる数): **5**(最初の1週間。下の「3. 最初の上限」)
- [ ] 有効: **最後に** 入れる(文面と地域を先に保存し、画面を開き直して残っていることを確かめてから)
- [ ] 検索の組み合わせ(rotation)は画面に欄が無い。DB の設定(`auto_pipeline_config.search_params.rotation`)に入れる。
      例(2026-10 の試験と同じ3都府県 × 3市 × 3業種。人が SQL で入れる):
      ```json
      { "prefectures": [
          { "name": "東京都", "cities": ["八王子市", "府中市", "世田谷区"] },
          { "name": "大阪府", "cities": ["堺市", "東大阪市", "豊中市"] },
          { "name": "愛知県", "cities": ["豊田市", "岡崎市", "一宮市"] } ],
        "industries": ["製造業", "建設・不動産", "サービス業"],
        "min_days_between": 30 }
      ```
      - 同じ名前の市町村(府中市・伊達市・明和町 等)は、別の県の会社を拾いやすい(試験で1件)。入れても「要確認」に回るが、少ない方がよい
      - 画面で設定を保存し直しても rotation は消えない(画面に無い項目は前の値を引き継ぐ)
- [ ] 確認(読み取りのみ): `GET /api/crm?action=auto-pipeline-config&project=locle` で `enabled:true`・`search_params.area.mode:"nationwide"`・`rotation` がある
- [ ] 確認: ozukanzukan の設定に `area` が無い(群馬県だけのまま)

## 3. 最初の上限

| 項目 | 最初の値 | 理由 |
|---|---|---|
| locle の1回に調べる数(daily_limit) | 5 | 新しい県の判定・宛名の不確かさを、人が全件見られる量にする |
| 1日に調べる数(`discover_daily_limit`) | 40 のまま | 2つのプロジェクトで別々に数える。locle は daily_limit で絞る |
| 保留からの自動の移し替え(`auto_release_hold`) | **切のまま** | locle の全国の会社は、最初の2週間は人が見てから送る |
| 1日の送信の上限(`daily_send_limit`) | 100 のまま | **2つのプロジェクトの合計**で数える。locle を増やすと ozukanzukan の枠が減る |
| locle の手での送信 | 1日10件まで | 返信・苦情・失敗の様子を見てから増やす |

上げる目安(2週間後): 下の指標が「止める目安」に1つも当たらなければ、daily_limit を 5 → 10 → 15 と1週間ずつ上げる。
`auto_release_hold` を入にするのは、locle の「要確認」の率が落ち着き、宛名の不確かさが ozukanzukan と同じくらいになってから。

## 4. 監視する指標(毎日。`docs/ops/毎日の収支の確認.md` の手順で読み取りのみ)

| 指標 | 見る場所 | 止める目安 |
|---|---|---|
| 調べた数・保留に積んだ数 | 自動パイプラインの記録(locle) | 3日続けて保留に積んだ数が0 → 検索の組み合わせを見直す |
| 「要確認」の率と理由 | 「あとで送る」(locle)の警告 `area_review` | 県が分からない・県が違う が新しく積んだ分の半分を超える |
| 見つけた県と住所の県が違う会社 | 同上(「見つけた県(◯◯)と住所の県(◯◯)が違う」) | 同じ名前の市町村の取り違えが続く → その市町村を rotation から外す |
| 公共・団体の名前 | 同上(「公共・団体の名前」) | 送ってしまった(=判定漏れ)が1件でも出る |
| 宛名の不確かさ | 「あとで送る」の宛名の警告 | 新しく積んだ分の3割を超える |
| 送信の結果 | 送信記録(locle): sent・uncertain・failed | failed が2割を超える |
| 返信・苦情・配信停止の依頼 | 返信の記録・メールの受信箱 | 苦情が1件でも出たら、その日の送信を止めて文面を見直す |
| 二重送信の防止で止まった会社 | 「あとで送る」の `cross_project` | 増えるのは正常。ozukanzukan と同じ会社に送っていないこと |
| 外部の API の費用 | Brave・Google・Anthropic の使用量 | 1日あたり想定(約1円 × 調べた数)の2倍を超える |
| Vercel の CPU・実行時エラー | Vercel → Usage・Errors | CPU の月の枠の8割を超えそう / エラーが続く |

## 5. 戻すとき

- 全国をやめる: 送信管理の画面で locle の地域を「群馬県だけ」に戻す(すでに積んだ保留はそのまま残る。送らないものは人がアーカイブする)
- locle の自動パイプラインを止める: 同じ画面で「有効」を外す
- 送信を止める: 送信待ちの行を保留にする、または `daily_send_limit` を下げる
- db-setup で足した列は消さなくてよい(使わなければ何も起きない)
